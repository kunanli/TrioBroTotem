# 連線、營地與分屏

## 營地與連線流程

```
Game Start
  → Server Host & Join
  → 在營地（Controlled Area）生成角色
  → 走到任務看板
  → 出發冒險
```

### 營地功能（確定：無任何數值加成）

**設計理由**：本作已定「僅章節內暫時強化、過關清空」。若營地提供裝備、補給或帳篷被動加成，等於偷開一條跨章節成長的後門，玩家會開始覺得「該先刷一下再來打」——這是輕度遊戲最該避免的心態。

因此營地的功能是**社交與準備**，不是數值：

| 功能 | 說明 |
|---|---|
| 展示進度 | 救出的動物住進來，多一頂帳篷、多一個可對話的角色。可見的進度條。 |
| 練習場 | 自由探索，練抓、丟、疊、推 |
| 換角色 | 走過去跟另一位玩家對話交換 possess，雙方同意才生效 |
| 任務看板 | 選章節、邀請、開始遊戲 |
| 失敗回歸點 | 章節失敗時退回此處 |

**外觀收集（可選）**：帽子、帳篷樣式、營火裝飾等純裝飾解鎖，不碰數值。

### 進入時的角色分配

進入營地時隨機分配角色；想更換必須與其他玩家協商交換。


## AI 夥伴規範

**成本原則：AI 只做被動配合，不做主動解謎。**

| AI 應該會 | AI 不需要會 |
|---|---|
| 跟隨隊伍、戰鬥、閃避 | 主動判斷謎題該怎麼解 |
| 被玩家抓起、投擲 | 主動發起抓取 |
| 被指示後站到定點、站上控制點 | 自己決定要去哪個控制點 |
| 疊高時自動就位 | 自己決定何時該疊高 |
| 扶起倒地的玩家 | — |
| 合體時接管自己的部位（自動瞄準） | — |

**設計要求**：每個謎題在文件中必須標註「AI 是否需要主動執行」。若是，該謎題必須改設計或提供替代解法。


## 分屏與鏡頭

### 分屏規格

| 項目 | 決定 |
|---|---|
| 本地分屏人數 | 2 人 |
| 第三人 | 線上連線或 AI |
| 分屏方式 | **動態分屏**——玩家靠近時畫面自動合併，散開時裂開 |

**為什麼動態分屏特別適合本作**：核心玩法是三個人黏在一起疊高、抓來抓去，**大部分時間玩家都在同一畫面範圍內**。疊高時分屏是浪費，合併起來更好看，且省效能。

**成本警告**：本地分屏不是「多開幾個鏡頭」。它意味著場景渲染兩次（效能預算砍半）、HUD 必須在半畫面下仍可讀、UI 要另做一套，且「2 人本地 + 1 人線上」的混合模式會提高連線架構複雜度（host 端需管理兩個本地玩家）。此項為本文件中成本最高的單一決定。

### 鏡頭規則（待細化）

需針對下列狀態定義鏡頭行為：

- 疊高時（誰的鏡頭優先？上層視野會被遮擋嗎？）
- 被抓起時（保有自由旋轉，見〈核心系統〉抓取與攜帶）
- 貓攀附在隊友背上時（被附著者的視野遮擋程度）
- 合體形態時（三人共用一個鏡頭？或各自保留？）
- 動態分屏的合併／分裂閾值與過場動畫
